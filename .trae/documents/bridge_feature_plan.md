# 桥梁功能设计计划 (Bridge Feature Design Plan)

## 1. 摘要 (Summary)
当前项目中，水面和道路是互斥的，玩家无法跨越河流建造道路。
本计划旨在实现“自动桥梁”功能。玩家可以直接使用现有的“道路”工具在已有的水面上点击，系统将自动在该位置生成桥梁模型（即底层是水，上层是桥）。该桥梁将被交通系统识别为合法道路，允许汽车在上方行驶。当玩家拆除桥梁时，桥体会消失并恢复为原来的水面状态。

## 2. 现状分析 (Current State Analysis)
- **建造逻辑** (`onPointerUp`): 当目标格子已被占用（`occupied = true`）时，除了同类型的道路替换/旋转，或者商业楼的样式切换外，其他建造行为会被拦截并直接 `return`。这就导致无法在水面（`water`）上方放置道路。
- **存储结构** (`cityMap`): 目前 `cityMap` 的每个格子（Key）只能存储一个对象（`{ type, mesh, mainKey }`）。如果是桥，它实际上占据了同一个格子的双重属性：水面 + 道路。
- **模型**：目前只有地面道路的贴花，缺乏具有立体高度和护栏的桥梁模型。
- **拆除逻辑** (`currentTool === 'demolish'`): 目前拆除会直接删除该格子在 `cityMap` 中的记录并移除模型。

## 3. 提出的修改 (Proposed Changes)

### 3.1 扩展存储结构以支持叠加状态
**文件**: `index.html` (全局逻辑)
- 桥梁本质上是“水面之上的道路”。为了避免大幅度修改 `cityMap` 的数据结构，我们可以定义一种新的类型 `'bridge'`。
- 在 `userData` 中增加 `baseType: 'water'` 来记录底层环境，以便在拆除时恢复。

### 3.2 创建桥梁 3D 模型
**文件**: `index.html` (新增 `createBridge` 函数，约 1100 行附近)
- 创建 `createBridge(x, z)` 函数。
- 桥梁包含：
  1. **桥面**：稍微抬高于地面的矩形板块，带有与普通直路（`straight`）相同的虚线。
  2. **护栏**：桥面两侧的实体围挡。
  3. **桥墩**：支撑在水中的柱子。
- 桥梁的 `userData` 应包含 `roadType: 'straight'` 和 `orientation`，以便现有的交通系统（`updateTraffic`）能无缝兼容并在上面通车。

### 3.3 修改建造逻辑 (自动转换)
**文件**: `index.html` (`onPointerUp` 函数内的 `occupied` 分支，约 2400 行附近)
- 当用户选择的工具是**道路类工具**（目前仅限直路 `road`），且点击的网格类型为 `'water'` 时：
  1. 获取该水面模型并将其从 `objectsGroup` 中移除。
  2. 生成桥梁模型 `createBridge`。
  3. 将网格记录从 `water` 更新为 `bridge`。
- 如果点击的已经是 `'bridge'`，则允许像普通道路一样进行**旋转**（修改 `orientation` 和 `rotation.y`）。

### 3.4 修改拆除逻辑 (保留水面)
**文件**: `index.html` (`onPointerUp` 函数内的 `demolish` 分支，约 2360 行附近)
- 当拆除的物体类型为 `'bridge'` 时：
  1. 从 `objectsGroup` 中移除桥梁模型。
  2. 重新生成一个普通水面模型 `createWater`，并加回 `objectsGroup`。
  3. 将 `cityMap` 中的该格子状态恢复为 `{ type: 'water', mesh: newWaterMesh }`，而不是直接删除 `delete(key)`。

### 3.5 交通与存档系统兼容
**文件**: `index.html`
- **交通生成 (`spawnCar`)**: 在寻找合法道路生成汽车时，将 `'bridge'` 加入到允许生成的 `roadKeys` 列表中。
- **交通导航 (`updateTraffic`)**: 在获取 `currentRoad` 时，将 `'bridge'` 视为合法的道路类型，执行直路（`straight`）的导航逻辑。
- **存档/读档**: 在 `getCityData` 和读取 JSON 时，支持 `'bridge'` 类型的序列化和反序列化。

## 4. 假设与决策 (Assumptions & Decisions)
- **桥梁类型限制**：为保持逻辑简单，初期仅允许**直路（Straight Road）**架设在水面上作为桥梁。弯道和十字路口的桥梁在现实和网格游戏中较少见且容易引起视觉穿模。如果在水面上点击弯道或十字路口，暂不生效或退化为直桥。
- **水面高度**：桥面需要比水面稍微高出一点（例如 `y=0.1` 或 `0.2`），由于汽车生成时 `y=0`，在桥面上行驶时汽车轮胎可能会穿过桥面。但由于目前的视角较高，细微的高度差在视觉上可以接受，后续可在 `updateTraffic` 中根据道路高度微调汽车的 Y 坐标，本计划初期优先跑通核心逻辑。

## 5. 验证步骤 (Verification)
1. **造桥测试**：在空地建水面，选择“直路”工具点击水面，水面应替换为桥梁模型。
2. **桥梁旋转**：连续点击桥梁，桥梁应能水平旋转（90度）。
3. **拆除恢复**：使用“拆除”工具点击桥梁，桥梁应消失，并重新显示水面。
4. **交通通行**：车辆应能在桥梁上正常生成，并顺畅地在桥梁与其他道路的连接处驶过，不发生掉头或消失。
5. **存档测试**：保存包含桥梁的城市并重新导入，桥梁应能正确加载。
